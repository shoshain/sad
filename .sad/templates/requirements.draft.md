# Requirements draft: <feature name>

> Output of `/sad-brainstorm`. Right-size the feature before any spec ink is spilled.
> Stays at the feature folder root until `/sad-specify` consumes it into `feature.spec.md`.

**Tier audience:** non-technical reviewer
**Status:** draft

## Problem
What problem does this solve, in plain language? Whose problem is it?

## Smallest viable scope
- One bullet per capability you would ship in the first cut.
- Keep this list short — items that "would be nice" go in *Out of scope*.

## Bounds
- Hard limits (length, count, frequency, time, money).
- Plain-text vs rich, public vs auth-only, single-user vs shared.

## Out of scope
- Things you explicitly will NOT do in this feature, so reviewers can stop suggesting them.

## Open questions
- Each as a one-line question. `/sad-clarify` is where they get answered.
- If none remain, write "None at this stage." — do not invent uncertainty.

## Assumptions captured
Anything you decided without evidence — flag it so `/sad-impact-forecast` can challenge it.
